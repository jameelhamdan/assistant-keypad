App Specific Instructions and Information:

Keypad: ESP32 hardware keypad (screen, 8 keys, knob) for answering Claude Code permission prompts and questions. Talks to the PC over Wi-Fi. macOS and Windows.

Layout:
- host/keypad/: Python host app (tray, hooks, server). core/ = sessions, transcript, markdown, dialogs. device/ = discovery, links, hub.
- host/tests/: pytest. fakekeypad.py is an in-process fake keypad.
- firmware/src/: C++ (PlatformIO). include/config.h holds PROTOCOL_VERSION.
- firmware/sim/: PC simulator that compiles the real app.cpp/ui.cpp.
- proto/PROTOCOL.md: wire protocol. docs/: architecture, development, hardware.

Commands (repo root): make setup, make test, make lint (ruff), make firmware, make sim.

Rules:
- The hook command imports only stdlib, keypad.ipc and keypad.dirs.
- Protocol changes that only add fields/messages keep `v`. Anything else bumps PROTOCOL_VERSION (config.h) and proto.VERSION.
- Session states are the five words in core/sessions.py PHASES; ui.cpp must use no others.
- Nothing is ever auto-approved; on timeout or pause Claude Code falls back to the terminal.

Where things live (host/keypad/):
- __main__.py, cli.py: entry point and commands (tray, agent, install, status).
- agent_cmd.py: agent process; core/agent.py ties sessions, dialogs, keypads, config together.
- core/hooks.py: Claude Code hook decisions (empty dict = no decision). hook.py is the hook shim and must stay stdlib-only.
- core/sessions.py: session registry + PHASES. core/transcript.py: follows session JSONL. core/markdown.py: Markdown for the screen. core/text.py: redaction, clipping, tool summaries.
- core/tune.py: the keypad's model and effort sliders (project .claude/settings.local.json). core/stats.py: health counters for `keypad status`.
- core/dialogs.py: dialog queue (one dialog owns keypads at a time, FIFO).
- device/hub.py: finds/connects/supervises keypads. device/pairing.py: USB setup (scan only during setup, provision). device/links.py: USB serial + Wi-Fi transports. device/discovery.py: mDNS.
- proto.py: wire messages. secure.py: pairing handshake, HKDF, AES-GCM.
- ipc.py + server.py: private channel/API between agent, hook, tray.
- claudecfg.py: installs/removes hooks in ~/.claude/settings.json.
- updater.py: self-update from GitHub releases (installed builds only; stdlib HTTPS client, no server).
- config.py: config.json settings. dirs.py: file locations. service.py: login item. firmware.py: bundled firmware / OTA.
- tray.py (menu), trayicon.py (icon), trayos.py, dialog.py: tray menu, OS workarounds, native pop-ups (also keypad setup).
- No web components: the project is the ESP32 firmware and the tray service only (no HTTP servers, pages or browsers).

Where things live (firmware/src/):
- main.cpp: setup/loop. app.cpp: protocol handling + key logic. ui.cpp: all rendering (320x170). model.h: state the UI reads.
- link.cpp: USB CDC + Wi-Fi/mDNS/AES-GCM. crypto.cpp: HKDF/AES-GCM. store.cpp: NVS settings. ota.cpp: firmware update. input.cpp: keys/knob. power.cpp: battery. mem.h: PSRAM alloc.
- text/text.cpp: pure wrap/glyph helpers (native-testable). include/config.h: pins, PROTOCOL_VERSION.

Tests:
- Host: host/tests/test_<module>.py per module (test_hook, test_hooks, test_agent, test_sessions, test_hub, test_dialogs, test_markdown, test_transcript, test_states...). Run one: cd host && .venv/Scripts/python -m pytest tests/test_x.py -q
- Firmware native: firmware/test/test_text. Simulator: firmware/sim (scenarios.py, test_sim.py; build with python firmware/sim/build.py, gallery via shots.py).
- UI change in ui.cpp/app.cpp: update sim scenarios/tests; docs/img/screens.png is generated by shots.py.

Other:
- packaging/: PyInstaller spec, macOS DMG, Windows installer. .github/workflows/ci.yml: tests + release.
- Version lives only in the git tag.
- Windows dev: venv at host/.venv/Scripts/.
